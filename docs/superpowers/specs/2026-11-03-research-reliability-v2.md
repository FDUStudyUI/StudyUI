# StudyUI 优化方案 V2：结合 DeepSeek 技术评审

日期：2026 年 11 月 3 日
状态：优化方案与核验记录；尚未实施本文提出的产品改动
讨论基线：v0.6.0，`feat/research-skills`，提交 `d1830c7b2652808203f4bae1b3e7b3bccdcffa69`

## 1. 核心判断

下一阶段以“批量光谱结果是否可信”为主线，按以下顺序推进：

**修正科学输出 → 建立独立评测与最小语义契约 → 验证真实/公开数据 → 增加受控诊断闭环 → 根据测量结果优化性能。**

DeepSeek 对项目主要矛盾的判断有参考价值：功能覆盖与工程测试已有基础，当前更需要补足科研有效性证据、关键结果的统计解释和真正的决策过程。

相较上一版，本方案做四项调整：

1. 将候选峰命名、规则暴露、检出统计与退化区间处理提升为首要修正。
2. 在开发闭环之前定义评分规则和保留测试集，以便判断自动修订是否有效。
3. 提前加入最小数据契约，明确观测对象、独立单位、分组和聚合历史；暂不建设覆盖全项目的大框架。
4. 保留“小范围、可核验的诊断闭环”作为近期技术深化目标，不将其无限延期；大规模自主编排、全面前端改造和传输层重写继续后置。

推荐主场景：**一批颗粒光谱 → 候选特征与检出状态 → 样品层统计 → 可复核结论。** 力学作为已具备基础的辅助案例，图像和文献模块维持现有功能与回归，不扩展新能力。

本次阅读了 DeepSeek 评审全文、上一版技术深化方案、本地材料模板及相关源码，并使用现有 Python 环境运行了针对性复算。未修改产品代码、安装依赖、合并 PR 或替换已有演示包。

DeepSeek 所称的独立复算与模拟，仍是外部评审提供的记录；只有下表明确列出的复算由本次实际执行。

核验产物：`StudyUI/.worktrees/research-skills/artifacts/deepseek-review-check.json`。该文件为本地分析产物，不属于已提交源码。

### 2.2 值得采纳的发现

### 2.3 需要修正后再采纳的建议

| 原建议 | 问题 | V2 的处理 |
|---|---|---|
| 最红端规则自然等于最低能耦合模式 | 最长波长与最低光子能量的关系不能证明某个检测峰的模式归属；噪声与其他模式也可能在红端 | 规则作为用户选择的候选策略，物理归属另需证据 |
| `n<3` 不能推断、`n≥3` 可以给可靠区间 | 这不是通用统计定理；n=2 的 Welch 计算可成立，但假设难验证、区间可能很宽；n≥3 也不能保证可靠 | 默认采用小样本保守政策，明确标为产品政策；各方法分别检查条件 |
| 所有检出率都给 Wilson 区间 | 二项区间要求相应独立性；同一样品内颗粒通常可能相关 | 检出比例始终可描述；推断区间依据独立单位或聚类结构选择 |
| 一律添加 cluster 层才正确 | 对独立单位先汇总可以是合理设计；增加字段不自动解决层级、配对或交叉结构 | 先定义估计对象和干预单位，再选择汇总或分层方法 |
| `DataFrame.attrs` 中的契约会自动进入指纹 | 当前指纹仅明确纳入单位等信息；复算中修改 `contract.granularity` 后指纹不变 | 契约显式序列化并独立绑定计划，attrs 作为便捷副本 |
| 所有角色必须选不同列 | 无技术重复时，同一实体可以同时是样品和独立单位 | 校验角色兼容性、唯一性和层级关系，允许有声明的合法同列映射 |
| 用粒度大小关系判断所有连接 | 点、峰、曲线、样品、组汇总不是统一的线性顺序；一条曲线可有多个峰 | 使用工具明确接受的输入语义与聚合关系，不采用通用 `≤` 规则 |
| 快速哈希可直接替代现有指纹 | 本次 `hash_pandas_object` 对 object 列中的整数 `1` 和字符串 `"1"` 给出同一哈希；现有类型语义会被削弱 | 先性能剖析；新指纹须有类型编码、版本与回归，不承诺与旧算法输出一致 |
| 直接去掉深拷贝、沿用上游哈希 | 可变表格会被后续修改，旧哈希或缓存可能绕过变化检测 | 先确立所有权与不可变边界，再优化复制和校验次数 |
| 运行产物全部逐字节一致 | 报告包含时间、目录与运行 ID | 规范化数值与语义结果做复现比较，文件哈希用于单次产物完整性 |

## 3. 优先修正：候选峰的语义与检出过程

### 3.1 输出与界面

新增面向用户的规范字段，如 `window_candidate_nm`、`selection_rule`、`candidate_count`、`ambiguous`、`detection_status`。保留完整候选集及其峰位、突出度、宽度、原始索引和选择原因。

旧的 `lambda10_*` 字段先作为版本化兼容别名，明确标记为候选含义，提供迁移说明与测试；暂不直接删除，以免破坏既有筛选、统计节点和示例。

物理声明单独记录为 `mode_assignment` 及证据/确认信息。人工勾选只记录判断来源，不自动构成物理归属的证明。

界面使用中文选项，例如“突出度最大候选”“最红端候选”；显示各自的选择依据。默认和确认要求由任务模板明确，报告无论采用何种规则都保留规则、窗口与歧义状态。

本次双峰复算中，两种规则分别选择 730 nm 和 790 nm，并均标为歧义候选。这说明规则会改变估计对象，必须进入计划、统计和追溯。

### 3.2 阈值策略

先提供三类清晰选项：显式阈值、旧版全谱相对阈值、经验证后的噪声参考阈值。旧策略保留兼容，但在界面显示阈值计算来源。

新噪声策略应明确背景/噪声窗口、估计方法、强峰污染和相关噪声处理。无可信噪声区域时提示需要确认，不默认为可靠的自适应结果。

MAD 与 `k·σ` 可以作为候选方法，但不能仅凭加入该公式就宣称消除组间检出偏倚。先用窗口外峰强度、噪声、基线和采样间隔变化实验比较误报、漏报及候选切换。

同一研究预先声明统一的阈值策略与校准程序，允许依据真实噪声和仪器条件计算阈值，不依据组别标签或期望结论临时调整。各组的信噪比与检出差异仍需报告。

峰间距支持物理单位；规则网格可换算为采样点，非均匀网格须在坐标域处理或明确重采样。具体值依据仪器分辨率和可分辨结构设置。暂不采用“至少两倍 FWHM”“肩峰谷深 20%”等未经本场景验证的统一默认值。

窗口边缘峰单独标记。扩大窗口需要用户确认或事先授权，保留原窗口结果用于比较。

### 3.3 检出状态与分母

每组同时报告总曲线、合格曲线、检出、歧义、无候选、计算失败与跳过数量。

“合格曲线中的检出比例”使用 `检出数 / 合格曲线数`；全部曲线的完成情况另列。计算失败不等于未检出。是否将歧义候选纳入某项描述统计须预先声明，不能静默排除。

检出子集的候选均值明确标为条件描述，不直接表述为全部颗粒的平均共振波长。观测检出比例也不命名为已校准的 `detection_probability`。

## 4. 优先修正：统计解释与小样本政策

### 4.1 产品默认政策

- 独立单位为 0 或 1：报告描述和不足原因，不将普通经验 Bootstrap 的零宽区间作为总体精度。
- 独立单位为 2：默认突出小样本与描述结果；如需特定模型推断，明确开启并记录方法、自由度、假设和区间。
- 独立单位达到 3 或更多：仍检查分布退化、层级、配对关系和方法适用性；样本量达标不等于推断可靠。
- 经验重采样分布退化：记录 `degenerate_resampling`，区分数据分辨率、重复值和模型假设，避免简单地把零宽解释为“确定”。

本次 n=2 Welch 示例仍返回有限 p 值与较宽区间，说明“不能计算”和“证据很弱”应分别呈现。SciPy 的方法接口及退化分布说明见文末参考资料。

### 4.2 先明确试验设计

基础契约要求记录：一行是什么、curve_id、sample_id、experimental_unit、group、技术重复/配对关系，以及处理条件实际施加在哪一层。

如果处理施加在样品上，同一样品的多个颗粒不自动构成多个独立试验单位。可先在样品层按预先声明的方法汇总，再比较样品；需要保留层内变异时，再使用经验证的分层方法。配对时按完整配对单位处理，交叉、重复测量等暂不支持的设计明确降为描述或要求外部分析。

若每组只有一个独立样品，增加上千颗粒只能改善该样品内部的描述，不能据此获得跨样品推断所需的独立重复。

### 4.3 区间输出

优先补原量纲下的组间差值区间及明确的独立单位数。根据设计选用 Welch、配对方法或按独立单位重采样；效应量区间在相应方法通过验证后加入。

基础契约不全时先保留描述路径，不从列名或颗粒数量推断独立性。检出比例的推断区间也遵循相同的单位与聚类条件。

分别呈现参数敏感性、统计区间和测量/校准误差。峰拟合中心与检测到的局部最大值也分列；局部拟合在峰模型、足够采样和残差诊断明确后实施，暂不以三至五点拟合承诺可靠标准误。

### 4.4 修正“缺失边界”建议

DeepSeek 的下界公式遗漏了缺失值的下限贡献。只有在**每个目标值都确实存在，且每个未观测值已知属于 `[L,U]`**时，才能给出均值的条件识别界：

```text
下界 = (n_det × mean_det + n_miss × L) / N
上界 = (n_det × mean_det + n_miss × U) / N
N = n_det + n_miss
```

这不是置信区间。未检出可能因为目标峰不存在、落在窗口外、信号不足或算法失败，不能直接假设所有未检出值位于搜索窗口。因此默认报告检出状态与条件均值；只有用户提供可辩护的存在性和取值范围假设时，才增加上述情景边界。

## 5. 评测与真实数据验证先行

### 5.1 从开发样例扩展到独立评测

先建设约 30 个具有明确预期的开发任务，覆盖关键正常路径与反例。随后以参数化生成器建立约 200–500 个任务的首版评测池；规模依据参数空间、运行成本和误差精度调整。

一个任务可能包含多条曲线或多个样品。不能将一批 500 条相关曲线直接当作 500 次独立任务验证。开发集和保留测试集按生成机制、参数区域和随机种子隔离，避免同一模板的近似副本泄漏。

优先覆盖：窗口内外峰竞争、肩峰与重叠、窗口边缘、非均匀采样、背景变化、噪声、疑似饱和、缺失、单位变换、ID 类型与层级结构。

### 5.2 基线与通过条件

对照至少包含：当前固定任务、加入语义/诊断但不自动修订、加入有限修订，以及人工配置相同工具的操作成本。对每个主要模块单独消融，保持数据、可用算法和资源预算可比较。

数值指标包括峰位误差、候选匹配和适用场景中的 FWHM/面积误差；决策指标包括错误自动执行、错误拒绝、正确停止和修订后改善；统计指标包括单位计数、覆盖率、第一类错误及区间宽度。

自动执行的硬约束，例如未授权扩窗、未知工具、篡改计划和预算越界，应在明确测试矩阵中全部拦截。候选正确率、检出率和修订效果的目标由开发集、科学用途与基线表现确定，再冻结到保留测试集。

不直接采用“切换率低于 10%”“覆盖率 0.90–0.98”“第一类错误小于名义值两倍”等统一门槛。不同峰间距、信噪比和试验设计应分层报告，避免整体平均掩盖失败区域。

覆盖率使用重复模拟并报告 Monte Carlo 误差。例如真覆盖率约 0.95、独立模拟 2000 次时，覆盖率估计的标准误约为 0.005；这只是模拟精度示例，正式次数按所需精度确定。

### 5.3 对 DeepSeek 模拟数字的处理

评审提到“不聚合技术重复时第一类错误约 25%，聚合后约 1.7%”。本次未复现其完整模拟脚本，不能直接作为 StudyUI 的实测成果。

建议独立实现并公开生成过程、随机种子、统计量、置换方式、p 值定义、模拟次数和误差区间。复算结果以实际记录为准；其意义是展示特定设计下伪重复的影响，不推广为普遍固定比例。

### 5.4 真实数据路径

优先读取少量授权真实数据或合法公开数据，先做 5–10 条的探索性复核，随后根据覆盖情况扩大。记录仪器条件、标尺/坐标、背景参考、文件来源和处理规则；团队成员独立标注并保留分歧，有条件时加入领域人员复核。

本次已核对对应论文的剑桥数据仓库页面，提供 `repository.zip`，页面标明 CC BY 4.0（另有说明的内容除外），并说明暗场/SERS 数据以 HDF5 保存。这是可执行的数据获取路线，不代表已下载、完成适配或获得了逐峰真值。

数值复核、候选一致性和物理模式归属分别记录。若论文数据没有明确模式标注，先评估可复跑与候选复核，不宣称验证了模式识别准确率。

## 6. 提前建立最小语义契约

### 6.1 只覆盖主路径

先覆盖导入、逐曲线分析、候选筛选、样品汇总、组间研究和报告，不要求一次迁移全部 62 个节点。

契约至少包含：schema 版本、记录粒度、角色映射、单位来源、实体/试验层级、技术重复与配对关系、聚合历史、上游派生来源及用户确认。

### 6.2 传递与校验

以结构化 Data 信封为持久传递来源，`DataFrame.attrs` 可保存便捷副本。串行化、批次打包、重命名、筛选、聚合、拼接和连接均需显式传播或更新，冲突时不能悄悄继承旧声明。

现有 `table_fingerprint` 未包含任意 `contract` 属性。本次修改契约粒度后旧指纹保持不变。因此应增加独立的规范化 `contract_sha256` 并绑定计划与缓存，或通过明确版本迁移引入新的指纹规则。保留旧算法用于旧版本校验，避免旧计划被误认有效。

检查规则采用具体输入契约：峰比较接收符合选择规则的曲线候选；按样品推断接收正确汇总和试验设计；一条曲线的多个峰不能未经说明计为多个独立样品。

`sample_id` 与 `experimental_unit` 在同一实体确为独立单位时可以合法同列；`x` 与响应列等具有不同意义的角色仍应分开。批次标识的加入不会自动把逐点表转换为曲线级或样品级数据。

旧流程没有契约时，根据操作风险提供兼容描述路径或要求补充设计。兼容不等于允许缺乏依据的推断。

## 7. 在评测支撑下实现最小诊断闭环

### 7.1 内部步骤

```text
体检 → 生成计划 → 契约/授权校验 → 分析 → 诊断
                                       ├─ 满足条件：稳定性/统计 → 报告
                                       ├─ 有可执行修订：建议 → 校验/确认 → 再执行
                                       └─ 条件不足或预算耗尽：needs_review
```

用户仍通过现有三节点流程操作，界面增加诊断、建议动作、前后差异和停止原因。普通使用继续选择、勾选和填空。

### 7.2 首版动作范围

首版最多支持少量已登记动作：应用用户预先允许的基线/平滑方案、采用已确认的阈值策略、生成稳定性对照、在试验设计充分时转入组间研究，以及停止并请求复核。

扩窗、更换候选物理解释、删除样品和改变独立单位不默认自动执行。任何依据 p 值反复调整检验、处理或排除规则的动作禁止进入自动策略。

建议最多两轮修订，另设总步骤、模型调用和时间预算。相同问题重复、未改善或达到预算时停止。改善标准预先定义为诊断量、候选误差或保真约束，不等同于“检出更多峰”。

### 7.3 规则与模型双模式

规则模式本地运行，提供确定性诊断与动作建议。模型辅助模式读取受控诊断摘要，在允许动作中提出有证据引用的选择，再由程序与用户确认校验。

诊断摘要的网络发送边界单独说明，尽量使用汇总量，避免自动附带完整原始曲线或可识别样品信息。

评测比较规则模式与模型模式。规则闭环属于受控自动化；只有模型实际依据中间结果参与规划或工具选择时，才说明相应的模型决策能力。若模型没有可测收益，保留规则主路径即可，不通过增加模型调用制造技术叙事。

### 7.4 决策账本

每步记录输入/契约/工具版本、触发证据、动作来源、参数变更、授权与确认、前后差异、预算和最终状态。用户可展开查看，导出进入报告；内部调试异常保留日志，界面给出可读错误码和恢复步骤。

## 8. 力学、图像与性能的取舍

### 8.1 力学辅助改进

在光谱正确性和评测主线完成后，增加用户确认范围内的拟合区间敏感性表、残差图及有效点数。保留既有模量和偏移强度输出，明确条件式拟合区间的不确定性与区间选择敏感性。

先核验加载顺序与数据约定：现有曲线函数默认要求坐标严格递增，但开启排序会改变记录顺序；这不能替代对加载/卸载路径的验证。循环或卸载试验不应简单排序成单调拉伸曲线。功密度注明积分范围，末端峰值提示可能截断，暂不自动推断断裂或改写物理阶段。

### 8.2 图像改进后置

后续再开展标尺 ROI、阈值/面积敏感性和适用的分水岭验证。像素量化、边界分割误差、标尺校准误差分别建模，暂不将统一的 ±0.5 px 当作完整尺寸不确定度。

### 8.3 性能先测量

现有代码存在重复哈希、复制与编解码，值得剖析；“10–50 倍提速”“2–3 倍内存”“近似超线性”目前不作为已证实结论。

分别测量：单长表逐曲线分析、多文件批次、规划/执行指纹、传输编解码、绘图与报告，记录各阶段耗时、峰值 RSS、载荷大小和失败位置。此前 1360 曲线的单任务压力记录不能直接代表多节点批次传输的成本。

优先减少同一次调用内经证明冗余的工作；随后才考虑不可变快照、解码缓存与 Arrow/文件引用。保留前导零、int/string、布尔、缺失、分类 dtype、索引、单位、契约和输入变更等语义不变量。指纹变化要版本化，不以直接信任上游哈希替代数据变化检查。
