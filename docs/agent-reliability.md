# StudyUI 执行状态、证据与界面验收

StudyUI 将模型建议、实际检查和工作流执行结果分别记录。以下约定适用于研究对话与画布运行按钮。

## 运行和恢复

提交研究任务后，服务端生成任务编号，状态和结果保存在运行目录的 `tasks.sqlite3`。刷新页面、切换会话后，可以重新打开会话查看任务进度。相同请求编号不会重复执行；同一会话同时只执行一个任务，旧消息接口、画布入口和审批执行也遵守这一限制。

| 状态 | 含义 |
|---|---|
| 排队中／运行中 | 后台已接受任务，尚未交付最终结果。 |
| 取消中 | 收到取消请求，正在等待当前模型请求或计算操作返回。 |
| 已取消 | 后续操作已停止，先前产生的文件和改动保留。 |
| 等待审批 | 当前任务创建了尚未批准的操作。 |
| 失败 | 模型请求、运行前检查或其他执行步骤未能完成；查看具体记录。 |
| 服务重启，任务已中断 | 旧进程已经结束，系统没有自动重放任务。 |
| 完成 | 本次对话处理已结束；科学结论是否成立仍以证据和检查范围为准。 |

取消采用检查点机制。无法强行中断正在执行的第三方数值计算，因此“取消中”不会提前显示成“已取消”。完成后的刷新仅恢复记录，不重新执行操作。因兼容需要保留的旧同步消息接口没有任务重连功能，新的界面使用持久任务接口。

运行时只支持一个服务进程、一个 worker。同一个运行目录不要同时启动多个服务。需要团队多用户部署时，应另行实现身份认证、租户隔离和跨进程调度。

## 检查结果的含义

- 文件名中的 `tensile`、`xrd` 等词只能帮助推荐分析方法或参考标准，不能证明标准符合性。无法核实的条件显示 `not_verified`，不会自动打勾。
- 首列递增检查给出实际检查的行区间、列号及观测结果。首列是否代表时间、波长或应变，需要结合仪器说明确认。
- 数据结构看板是此前的检查记录。它不能证明文件尚未改变，也不能代替单位、试样几何和测试条件的核实。
- 节点连接按实际输入、输出名称及类型验证。不存在或有歧义的端口会报错，不自动连接到唯一剩余端口。
- 除零或定义域错误提示用户检查公式和数据，不建议直接添加微小常数来掩盖物理问题。

## 文件和代码草稿

上传要求选择有效研究会话，遵守项目权限。相同文件名再次上传会保存新版本，保留原始字节和 SHA-256，不覆盖旧数据。

模型代码可以复制或保存为 `.py.txt` 审核草稿。草稿可下载，不会加入组件目录或执行。可执行扩展继续通过已审核版本的 Skill 和离线 Docker 沙箱接入。

路径授权要求用户明确提供完整路径，或在当前工作目录中明确指定相对路径。正文中的路径应使用引号或反引号；同名文件不共享授权。上传和演示数据按钮会生成带引用的路径提示。

## 对话排版

Markdown 与数学公式使用随应用安装的本地资源，普通使用不依赖外部 CDN。支持标题、列表、引用、表格、代码块及行内、独立公式。代码块保留代码原文，复制和导出的 Markdown 保留公式源代码。长表格、代码和公式在各自区域内横向滚动。

模型正文按限长快照持续显示，刷新可以恢复已收到的正文。未完成或无效的公式保留可读源文本；取消或失败后的部分输出明确标为未完成。模型生成的 HTML 不作为任意页面脚本执行，外部图片不自动请求。

数学渲染按照 [KaTeX 的不可信输入配置](https://katex.org/docs/security)限制宏展开和尺寸；Markdown 的解析行为以 [markdown-it 文档](https://markdown-it.github.io/markdown-it/)为依据。具体随包资源版本、许可证及哈希见界面资源目录。

## 可复现验收

在 `packages/materials-quality` 中，安装开发依赖后执行：

```sh
python -m pytest -q
ruff check src components tests scripts examples
ruff check ../../scripts --config pyproject.toml
python -m scripts.evaluate_agent_boundaries
python -m scripts.verify_install
```

浏览器验收需要安装 `.[ui-test]` 与 Chromium，运行：

```sh
python -m playwright install chromium
python -m pytest tests/test_agent_ui_browser.py tests/test_agent_rich_rendering.py -q
```

`evaluate_agent_boundaries` 使用固定的对抗输入与手写预期，输出每个场景的输入摘要、预期、实际结果和判定。其范围包括证据、文件身份、端口、流式截断和取消；它不评价在线模型的科研能力。浏览器测试使用可控的离线模型替身，不消耗用户 API 额度。实际模型的任务成功率、费用和延迟，需要另设带数据版本、模型版本及预算的评测。
