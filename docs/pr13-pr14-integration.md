- 统一工作流客户端名称和搬迁后的目录路径，修正新增组件注册和导入。

- 保留 #14 的任务历史清理与 #13 的可恢复任务状态；修复相关测试的接口兼容。
- 从已提交示例内嵌数据恢复缺失的 SQLite 样例，校验 SHA-256，保证新检出环境能构建示例。

## 使用与边界

- 常用入口是 DSH Web；需要明确选列、填单位、设置拟合范围或查看人工确认时，打开材料任务面板中的“参数表单与运行记录”。该入口复用原工作台，在新标签页打开。
- DSH 对话与原工作台会话仍各自管理，工作流文件共享；未实现两套聊天记录的自动合并。
- 直接运行队列与 MCP 队列复用同一实现，但属于各自进程，队列状态本身不跨进程共享、不在重启后自动重放。执行账本和科学计算检查点保存在磁盘；原工作台保留人工确认与恢复流程。
- 取消在检查点停止后续操作，不强行中断正在执行的第三方原生计算。
- 3 次实际模型建流只证明这三个样例通过，不作为模型总体成功率。真实仪器评测中的方法参数契约检查，与材料专家盲评是两件事；本次未收集专家盲评分数。
- pymatgen / PyBaMM 是可选依赖。未安装时组件明确提示缺少依赖；接口与缺包行为通过测试，不将模拟后端测试写成真实求解器验收。

## 可复现命令

在 `materials-quality` 目录使用项目依赖环境执行：

```powershell
python -m pytest -q
python -m ruff check src components tests scripts examples
python -m ruff format --check src components tests scripts examples
python -m scripts.build_science_components --check
python -m scripts.build_science_examples --verify
python -m scripts.evaluate_agent_stability --output artifacts/agent-stability --repeats 3
python -m scripts.evaluate_material_instruments --output artifacts/material-instruments --repeats 3
```

Windows 浏览器测试可通过 `PLAYWRIGHT_CHROME_EXECUTABLE` 指向已安装 Chrome。实际模型测试需配置官方端点、模型名与密钥环境变量，再添加 `--live`；密钥不进入仓库或测试报告。
