# Agent 自主建流复测记录

日期：2026-11-05。本次将上一轮五个验收流程移入可恢复目录后，重新给 Agent 研究目标、公开来源和本地文件路径；请求中不提供节点名称、节点参数、表头或读取范围。下述工作流和修改均由 StudyUI Agent 的工具调用产生，验收只读取 Agent 生成的流程、报告及附件。

这些数据集曾用于前一轮调试，针对发现的问题改进了通用文件检查、节点目录说明和系统提示，因此这是**对已见数据的自主复测**，不是对全新领域或新数据的独立泛化评估。所有源文件哈希和数据来源见[历史输入记录](raw-data-agent-experiments.md)。

CSV、图件和报告通过会话下载接口检查大小及 SHA-256；五个最终工作流通过画布接口重新读取，校验节点与连线句柄。该校验不等于逐条视觉检查或论文复现。各会话保存在本机 StudyUI 中，原始文件、工作流和会话数据库不纳入 Git。

Agent 工具层本轮补充了用户指定文件的结构检查、候选表头和数值覆盖统计；支持精确解析 Zenodo 记录对应的 DataCite 元数据；组件目录提供条件字段、输入类型和表格字段结构；模型空答复和短暂连接错误可自动重试。为避免误传，原始数值行不进入文件检查结果；已知聚合节点的运行结果如果包含可解析的数据记录，可提供有界派生摘要，单样本组不返回可能还原个人测量的均值。PbS 实际运行中统计节点仅返回表格行数和列名，未显示数值摘要；表格已导出，但不能据此声称模型看到了这些统计数值。

新增 Markdown 报告工具后，仅对 PbS 追加报告请求做了实际模型验证；其余四例的 HTML 主要是节点运行记录，不能据此声称它们已有同等完整的叙述性报告，也不能推断 Agent 会在新的单轮任务中稳定调用该工具。观察到的局限仍包括模型服务连接中断、内部工具调用较多、部分失败后的诊断产物留在会话中，以及模型可能给出错误的科学推理。五个案例不能证明 Agent 已对任意材料实验稳定工作；需要继续用未用于调教的新数据和不同研究目标做独立验证。
