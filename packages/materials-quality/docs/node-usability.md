# 节点怎么用，以及本轮优化清单

普通任务先用表单。只有需要复用旧配置或设置少见的复杂对象时，才到高级设置选择 `json`。
52 个正式节点均保留；44 个科学节点按任务生成不同控件，原有共享规则和六项质检也有表单。
本轮修改界面和参数接入，不改变科学计算定义，也不覆盖实验原始文件。
可先导入[四份新手上传练习](../examples/form_flows/README.md)，或直接运行[九份内嵌合成数据示例](../examples/science_flows/README.md)。

## 从材料拉伸数据开始

1. 添加“表格文件读取”节点，在“上传源文件”中选 CSV；也可以填写运行 Langflow 的电脑能访问的路径。
2. 将它的“结果表格”连接到“力学性能分析”的“输入表格”。需要连续来源记录时，再连接“结果与追溯”。
3. 在分析节点选择应变列、应力列、应变单位和应力单位。列名候选中没有自己的名称时，可以输入实际列名。
4. 填写经过实验依据确认的弹性拟合区间下限和上限。合成拉伸例的应变区间是 `0` 到 `0.0008`，
   应变单位 `fraction`，应力单位 `MPa`；这些数值不适用于所有真实材料。
5. 运行后查看“运行摘要”和“结果与追溯”，其中包含弹性模量、屈服强度及采用的方法、单位和参数。
6. 把原始应力—应变表接到“力学曲线绘图”，选择对应列；把分析报告接到追溯端口。
   把相关“结果与追溯”接到“报告导出”的“报告来源”，运行后可打开生成的 HTML。

示例中的合成曲线用于检查程序，不代表真实试验结果。图表的数据性质也应选择为合成数据。
文件生成在运行 Langflow 的电脑或服务器上，“生成文件”端口列出路径和哈希。

## 不同控件怎么填

| 控件 | 操作方法 | 例子 |
|---|---|---|
| 方法、单位下拉框 | 选择一种方法；切换后相关控件随之显示 | `linear`、`MPa` |
| 列选择 | 选择候选列，或输入实际列名 | `strain`、`stress` |
| 多列选择 | 一次添加一列；不需要的项可以移除 | 多个统计特征列 |
| 有序重复列表 | 按顺序逐项添加，允许值重复 | RGB 的 `255, 0, 0`、命令参数 |
| 数值、上下限 | 直接填数值；区间下限须小于上限 | 弹性区间、像素标尺 |
| “自定义…”开关 | 默认关闭，保留方法自动设置；需要时开启并填写 | 图宽、dpi、随机森林最大深度 |
| 键值编辑器 | 左边填列或项目名，右边填对应内容 | 列名 → 单位 |
| 规则表 | 打开编辑器，按表头填一行或多行规则 | `stress` 的最小值和最大值 |
| 高级 JSON | 仅在 `json` 模式采用完整对象；表单模式不合并它 | 旧流程、复杂参考谱对象 |

两种配置方式互相独立，避免表单默认值悄悄覆盖旧 JSON 的设置。
`0`、`false` 和空列表具有各自意义，不会统一当成“没填写”。不填可选数值时使用自动设置，
不会把“自动”误传成 0。切换方法会保留编辑值，但执行时只采用当前方法适用的参数。

## 共享质量规则

在“共享质量规则”节点中选择启用的检查，编辑必需列、别名、字段类型、数值范围、单位规则等。
把“原始表格”和“共享规则”分别接到检查节点的对应端口。已连接的共享规则优先于检查节点本地规则。
例如只启用结构检查，填 `strain` 为必需列；把它改成数据中不存在的列，再运行会产生相应发现。

共享规则只表达检查要求。质检报告中的发现需要人工判断；清洗和单位换算应通过明确的处理节点完成。
单位检查在原生表单模式下，未开启换算时不显示换算端口；明确开启后才显示。
换算受阻会报错，并提示查看检查报告，不会用假空表表示成功。
连接共享规则时以共享规则的换算设置为准，节点本地开关不能覆盖它。
旧 JSON 模式保留原端口以兼容已有报告链；没有换算结果时，兼容空表会标记
`table_available=False` 和原因，不应接入后续科学分析。

## 这轮实现的优化

| 用户遇到的问题 | 当前处理 |
|---|---|
| 必须手写大段 JSON | 普通参数拆成原生表单；复杂少见对象放在高级设置 |
| 所有节点都长一样 | 不同任务使用不同图标、方法、字段和帮助说明 |
| 不知道应接什么 | 输入按实际任务生成，区分主数据与可选追溯；报告集合仅保留给确有多来源需要的节点 |
| 图像读取出现空表格 | 图像读取等不产生表格的任务不提供表格端口；报告明确标记无表格 |
| 真正筛选到零行时被误判 | 真正的零行表仍是表，报告记录 0 行；与无表格结果分开 |
| 方法切换后很多无关参数 | 根据当前方法显示控件，只把适用参数传给算法 |
| 模型任务选择被上游覆盖 | 明确区分重新训练、已有模型、已有预测值；任务选择决定执行路径并记录到追溯中 |
| 输入框顺序难找 | 流程保存字段顺序，先数据输入，再列、单位和参数；区间先下限再上限 |
| 可选数值留空却传入 0 | 增加“自定义”开关；关闭时省略参数 |
| 多个相同值无法输入 | 对 RGB、坐标、网格、命令参数等采用允许重复的有序列表 |
| 参数写错难定位 | 错误指出具体字段；整数、有限数值、区间和结构在接入处检查，算法继续检查科学适用条件 |
| 上传文件不方便 | 真实文件读取节点直接提供上传；只显示支持的文件类型 |
| 不知道结果从哪来 | 保留参数、源文件哈希、单位和来源链；已连接的追溯端口在导出流程中保持可见 |
| 旧流程升级怕丢配置 | 提供保留原文件的迁移工具；遇到自定义代码或未知参数会报告，不静默删除 |
| 不知道如何复现 | 保留可导入示例、测试和独立界面验收脚本；评委运行不依赖个人 skill |

列候选会在 Langflow 实际提供表格元数据时更新，也可手动输入。
这不等于上传文件后所有下游节点都能自动知道列名；当前 Langflow 对未执行的跨节点数据不保证提供列信息。

## 旧流程如何升级

先导出旧流程 JSON，在本包目录运行：

```powershell
python -m scripts.migrate_flow_ui path/to/old-flow.json
```

默认生成同目录的 `old-flow.ui-v2.json`，保留原文件，不覆盖已存在的输出。
只升级可确认来源的正式节点，保留节点 ID、位置和旧参数；旧配置采用 `json` 模式以保持原意。
自定义代码及不支持的非空参数保留并列在迁移报告中；指向已取消端口的连线会明确报错，须人工选择正确数据输出。
在新文件验收通过后再决定是否替换团队正在用的流程。

## 后续优化建议，尚未宣称实现

| 优先级 | 建议 | 验收方式 |
|---|---|---|
| 高 | 运行读取节点后，给下游提供可复用的数据集字段目录 | 同一次上传，分析、绘图和质检选择器都看到实际列名；换文件后旧字段被提示 |
| 高 | 材料类型与试验模板，集中配置单位、标距、截面积及拟合区间 | 一个设置面板驱动多个节点，导出后参数和单位仍可追溯 |
| 高 | 运行前统一预检，集中列出缺文件、缺列、单位及标定问题 | 运行计算前一次显示可定位到节点和字段的问题 |
| 高 | 数据预览与单位确认，显示前几行、行数、缺失情况 | 上传后不运行复杂模型即可确认读对了列、分隔符和单位 |
| 中 | 表单配置预设的保存、命名和版本比较 | 队员复用同一套规则，能看出修改了哪些参数 |
| 中 | 直接下载生成文件及一键打包报告、图片和参数 | 远程服务器运行后，用户能在浏览器拿到完整结果，不需要找服务器路径 |
| 中 | 上传状态和选中文件的明确确认 | 上传完成后清楚显示当前选择，进度期间避免误点，确认按钮与真实选中状态保持一致 |
| 中 | 新手教学流程、分步提示和一键恢复示例 | 不看代码即可完成上传→质检→分析→绘图→导出的完整链 |
| 中 | 长任务进度、取消和失败重试 | OCR 或大数据运行中可看进度，取消后不留下被误认为完成的文件 |
| 中 | 字段目录缓存与大流程性能优化 | 用真实大流程测量启动、方法切换和输入编辑耗时，再优化热点并验证版本更新会使缓存失效 |
| 中 | 方法适用条件和结果解释卡片 | 选择检验/模型时看到样本量、独立性、配对与单位要求，并随报告记录 |
| 中 | 结果差异比较，人工修订前后并排展示 | 同一份原始数据不同规则/版本可核对发现数和力学指标变化 |
| 低 | 常用节点收藏、中文标签筛选、统一键盘操作 | 新手能迅速找到常用节点，编辑器中的键盘操作一致 |
| 低 | 任务运行记录、耗时和产物目录管理 | 可追踪哪次运行生成哪些文件，清理前能确认依赖与保留策略 |

这些建议包含需要 Langflow 前端或团队产品层支持的功能，不通过随意增加计算节点参数来代替。
界面验收范围、测试结果和已知限制随本轮验收记录一起维护。
